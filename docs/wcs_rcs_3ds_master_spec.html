WCS ↔ RCS ↔ 3D Sorter · Master Spec

WCS ↔ RCS / 3D Sorter 통합 인터페이스 정의서 실시간 연속 운영. 로봇이 트레이 상품을 목적지(슈트 또는 3D 셀)에 한 번에 전량 틸트. ※ PLC 주소는 3DS 제공 맵 기준(§7), 시간값은 예시(현장 조정).

00 개요 & 시스템 구성

WCS(자사, 오더 보유)가 RCS(AGV·로봇)와 3D Sorter(VEICHI PLC)를 연동한다. 로봇이 인덕션에서 트레이를 받아, 목적지(슈트 또는 3D 셀)에 상품 전량을 한 번에 틸트한다.

  • 실시간 연속 운영 — 배치(차수) 시작/종료 개념 없음. 인덕션부터 바로 처리(작업 데이터 수신·시작·종료·결과 전송 IF 제외).
  • 목적지 = chuteNo — 슈트/3D를 하나의 번호로 식별(메시지에 destType 없음). 투입 보고도 슈트/3D 구분 없이 동일.
  • 한 번에 전량 틸트 — 한 트레이에 같은 상품 여러 개(qty)를 싣고, 한 목적지에 전량을 한 번에. 부분 투입 불가.

05 목적지 조회 (IF-05) 사유

WCS가 목적지(chuteNo)와 수량을 판정한다. BUSY(분류 중·이동 중)는 일시적이라 그 목적지로 그대로 배정(도착 후 IF-08 상태에서 ready가 되면 투입). FULL·PAUSED는 목적지 타입별로 갈린다 — 슈트는 곧 비워지니 IF-05는 OK(보내고 대기, readiness는 IF-08 푸시로 별도 전달), 3D 소터는 PAUSED·셀 만재면 NG(가부 조회 IF-08 폐지로 도착 후 거를 수 없어 IF-05에서 막는다).

WCS 사유(내부)RCS 수신동작
NORMALOK · chuteNo전량이 한 곳에 들어감 → 그 목적지로 진행
BUSY (분류 중·이동 중)OK · chuteNo일시적 → 그 목적지로 보냄. 도착(IF-09) 후 소터가 IF-08 상태에서 ready가 되면 투입
FULL / PAUSED (목적지 타입별)NG 대기 / OK슈트: full/paused여도 IF-05는 OK(보내고 대기 — readiness는 IF-08 푸시로 별도 전달). 3D 소터: PAUSED면 NG(예외 없이 차단), 셀 기준(SorterCanAcceptBarcode)으로 못 받으면 NG(FULL); OFFLINE은 IF-05에서 보지 않는다(셀이 있으면 도착 후 푸시 ready 대기)
OVERNG 대기전량이 한 곳(슈트/3D 한 셀)에 안 들어감 → 전량 가능할 때까지 AGV 대기
COMPLETED / NO_DEST / OFFLINENG 대기보낼 곳 없음 → AGV 대기(이동 안 함). OFFLINE은 대체 3D/보류
NG·대기 그룹: 소터 FULL/PAUSED(소터만 — 받을 수 없음) · OVER(전량 안 들어감) · COMPLETED/NO_DEST/OFFLINE(보낼 곳 없음). OK·진행은 NORMAL·BUSY + 슈트 FULL/PAUSED — BUSY와 슈트 FULL/PAUSED는 그 목적지로 보낸다(슈트는 곧 비워지고 readiness는 IF-08 푸시로 전달). 소터만 FULL/PAUSED에서 NG(IF-08 가부 조회 폐지로 도착 후 거를 수 없어 IF-05에서 차단). ※ 목적지 타입 분기는 wcs_rcs_interface_kr.html §6·실코드(RcsController.QueryDestination)와 정합.

06 목적지 상태 알림 (IF-08) — WCS → RCS 푸시

기존 투입 가부 조회(RCS 폴링)를 폐지하고, WCS가 목적지 상태를 변경 시마다 RCS로 푸시한다. 키는 chuteNo — 일반 슈트와 3D 소터 슈트를 동일 인터페이스로 알린다. 페이로드는 단일 ready 하나(chuteNo · ready · timeStamp). RCS는 층도 사유도 모르고 ready만 본다 — true면 투입, false면 대기. ready 산출: 일반 슈트 = !full && !paused(WCS가 만재/정지 관리) · 소터 슈트 = online·!full·!paused·Ready=1·CurFloor=2. 이로써 RCS가 만재·정지 슈트엔 틸트하지 않는다.

푸시 상태RCS 해석동작
ready=true (OK)수용 가능RCS 투입(틸트)
ready=false (NG)대기지금 받을 수 없음(분류·이동 중·만재·정지·오프라인) — 다음 푸시에서 ready 시 투입
full / paused / online=false소터 차단대기 — 해소 푸시까지 보류
도착 보고(IF-09) → 3DS 정렬(2층 고정) — RCS가 AGV를 슈트에 도착시키면 IF-09(pId·chuteNo·agvNo)를 보내고, WCS가 3DS를 2층(운영 고정층)으로 정렬한다(TgtFloor=2 D6, §07, ==0일 때만 씀). 정렬돼 ready가 되면 IF-08로 알리고 RCS가 투입. RCS는 층을 모르고 ready만 받는다 — 층은 WCS↔3DS 내부 사정.

07 3DS PLC 레지스터 + 핸드셰이크

영역워드/비트방향설명
셀 지정 (C) · IF-11C_CellNo(D0) · C_Seq(D1) · C_Flag(D4.0)WCS→PLCWCS가 셀 지정 후 C_Flag=1
적재 완료 (R) · IF-12R_CellNo(D2) · R_Seq(D3) · R_Flag(D4.1)PLC→WCSPLC가 적재 후 R_Flag=1
상태 · 층Ready(D4.2) · CurFloor(D5) · TgtFloor(D6)WCS read / writeReady(0=분류 중→BUSY) · 현재 층(1/2) · 목표 층(0=없음)

핸드셰이크 규칙

  1. 쓰기 전 해당 Flag=0 확인 — 아직 안 읽힌 값을 덮어쓰지 않도록(C_Flag / R_Flag 각각).
  2. C 영역: WCS가 C_Flag=0일 때 C값 쓰고 C_Flag=1 → PLC가 C값 읽고 C_CellNo·C_Seq·C_Flag=0 클리어 후 적재.
  3. R 영역: PLC가 R_Flag=0일 때 R값 쓰고 R_Flag=1 → WCS가 R값 읽고 R_Seq==C_Seq 대사 후 R_CellNo·R_Seq·R_Flag=0 클리어.
  4. 층 폐루프(2층 고정): WCS가 TgtFloor==0이고 (CurFloor≠2 또는 분류 중)일 때 TgtFloor=2 쓰기 → 2층 아니면 이동, 분류 중이면 분류 후 2층 복귀 → 도착 시 PLC가 CurFloor 기입(TgtFloor 유지) → WCS가 CurFloor=2 확인되면 ready 산출. TgtFloor는 분류 시작(BUSY 진입) 시 0으로 클리어. TgtFloor≠0이면 덮어쓰지 않아 핑퐁 차단. ※ 메커니즘은 다층 가능하나 운영은 2층 고정.
“쓰는 쪽은 Flag=0 확인 후 쓰고 1, 읽는 쪽은 읽고 0.” C는 WCS가 쓰고 PLC가 클리어, R은 PLC가 쓰고 WCS가 클리어 — 대칭. 틸트 낙하 대기는 PLC가 N초 지연으로 처리(WCS 측 지연 없음). 모든 레지스터는 Holding Register(읽기 FC03 · 쓰기 FC06/16)이고 C_Flag·R_Flag·Ready는 워드 D4의 비트0·1·2다 — 한 비트만 바꿀 땐 D4 read-modify-write(상대 비트 보존). 주소는 3DS 제공 맵(D0~D4) + 층 신설(D5·D6).

08 핵심 플로우

① 인덕션·목적지 조회→ ② 도착 보고(IF-09) → 3DS 정렬(2층)→ ③ 3DS 상태 푸시 → RCS 투입 판단→ ④ 투입(슈트/3D 공통)
  1. ① 인덕션·목적지 조회 — 스캔(qty) → (판독 실패 시 NO_READ·재스캔/리젝트) → IF-05(라인 투입 기록 + 목적지·수량 판정) → OK·chuteNo(NORMAL·BUSY) / NG·대기(FULL·PAUSED·OVER·COMPLETED·NO_DEST·OFFLINE).
  2. ② 도착 보고 — IF-09: AGV가 슈트 도착 → WCS가 3DS를 2층(고정)으로 정렬(TgtFloor=2, ==0일 때).
  3. ③ 목적지 상태 알림 — IF-08: WCS가 목적지(슈트/소터) 상태 변경 시마다 RCS로 푸시(단일 ready, OK/NG · 키=chuteNo). RCS는 ready=true일 때 투입, 아니면 대기.
  4. ④ 투입 — IF-10 투입 보고 → IF-11 셀 지정(C_Flag=0 확인 후 1) → PLC가 C 읽고 초기화 → 적재(R_Flag=0 확인 후 1) → WCS R_Flag 폴링 → R 읽고 초기화. 이후 분류 후 복귀(TgtFloor 층으로 이동 → 도착 시 CurFloor 기입).

10 확정 사항 (PLC 협의 완료)

  • PLC가 주는 상태 = 수용 가능 여부(Ready=D4.2) — Ready=0은 분류 중 또는 이동 중(둘 다 받을 수 없음). FULL(만재)·PAUSED(일시정지)·OFFLINE은 WCS가 판단한다(만재=예약/수량, 일시정지=운영 상태, OFFLINE=폴 타임아웃). BUSY/FULL 구분용 별도 PLC 비트는 두지 않는다.
  • TgtFloor 쓰기 = 0일 때 + (CurFloor≠2 또는 분류 중) · 항상 2 — TgtFloor==0이고 2층이 아니거나 분류 중(BUSY)이면 TgtFloor=2를 써서 2층으로 이동/복귀시킨다(운영 2층 고정). 진행 중(≠0)엔 덮어쓰지 않아 핑퐁 차단. 도착 시엔 CurFloor만 기입(TgtFloor 유지), 분류 시작 시 TgtFloor=0 클리어. FULL/PAUSED/OFFLINE은 쓰지 않고 대기.
  • 플래그 위치 확정 — C_Flag=D4.0 · R_Flag=D4.1 · Ready=D4.2 (3DS 맵). 같은 워드(D4)라 한 비트만 바꿀 땐 read-modify-write.
