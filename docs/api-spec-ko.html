1. 미작업 차수 요청

필드명타입길이필수여부설명비고

💡 Request URL 예시 (Query String)

GET /api/v1/works/unprocessed?bizDay=20260327

반환 데이터 (Response)

필드명타입길이필수여부설명비고

batchString3Y배치001
itemsArray-Y미작업 데이터 목록배열(List) 형태

2. 투입 데이터 송신

작업 투입에 대한 데이터를 서버로 전송합니다.

POST /api/v1/works/input

요청 데이터 (Request)

필드명타입길이필수여부설명비고
bizDayString8Y날짜20260327
batchString3Y배치001
inductionNoInteger-Y인덕션 번호1
chuteNoString3Y슈트 번호001
pIdInteger-YPID12345
barcodeString20N바코드test001blk100
statusString2Y상태OK 또는 NG
reasonString255N사유status가 NG일 경우 필수
inTimeString20Y투입 시간2026-03-27 14:52:04
qtyInteger-N한 번에 투입된 동일 품목 수량1~9999, 생략 시 기본값 1

※ 동일 품목 N개를 묶음 투입할 때 qty = N 으로 한 번만 호출합니다. 생략 시 qty는 1(단일 품목)로 처리됩니다. 서버는 미처리 행 N개를 한 번에 처리하며, 남은 행이 N개 미만이면 아무것도 처리하지 않고 status: "F"를 반환합니다.

💡 Request JSON 예시

{
  "bizDay": "20260327",
  "batch": "001",
  "inductionNo": 1,
  "chuteNo": "001",
  "pId": 12345,
  "barcode": "test001blk100",
  "status": "OK",
  "reason": "",
  "inTime": "2026-03-27 14:52:04",
  "qty": 3
}

반환 데이터 (Response)

필드명타입길이필수여부설명비고
statusString1Y처리 상태S: 성공, F: 실패
messageString100Y처리 내용Success 또는 Fail

💡 Response JSON 예시

{
  "status": "S",
  "message": "Success"
}

5. 박스 데이터 수신

박스 분류 기계가 전송하는 박스 단위 마감 데이터(박스번호, 슈트, 내품 바코드 목록)를 수신·저장합니다. Results 와 달리 바코드 등록 여부를 검증하지 않고 단순 저장합니다.

※ RCS 측에서 박스 마감(패킹 완료) 기능 구현이 가능하다면, 구현 후 박스 마감 시 본 엔드포인트로 박스 데이터를 전송해 주시기 바랍니다. 현재 구현이 어렵다면 본 엔드포인트는 사용하지 않아도 무방하며, 나머지 4개 엔드포인트 동작에는 영향이 없습니다.

POST /api/v1/works/box

전송 데이터 (Request)

필드명타입길이필수여부설명비고
bizDayString8~10Y업무일자"20260624" 또는 "2026-06-24"
batchString1~10Y배치번호"001"
boxNoString1~50Y박스번호"BOX-001". (bizDay,batch) 내 유일해야 함
chuteNoString1~10Y슈트번호"3" 또는 "003". 서버가 3자리 zero-pad 적용
itemsArray-Y내품 목록최소 1개 필수
↳ items[].barcodeString1~100Y내품 바코드영문자·숫자·하이픈·언더스코어
↳ items[].qtyInteger-N해당 바코드의 수량1~9999, 생략 시 기본값 1
endTimeString1~50N박스 마감 시간"2026-06-24 10:00:00"

💡 Request JSON 예시

{
  "bizDay": "20260624",
  "batch": "001",
  "boxNo": "BOX-001",
  "chuteNo": "3",
  "items": [
    { "barcode": "BC-001", "qty": 2 },
    { "barcode": "BC-002", "qty": 1 }
  ],
  "endTime": "2026-06-24 10:00:00"
}

반환 데이터 (Response)

필드명타입길이필수여부설명비고
statusString1Y처리 상태S: 성공, F: 실패
messageString100Y처리 내용Success 또는 Fail

💡 Response JSON 예시

{
  "status": "S",
  "message": "Success"
}

6. 실패 응답 (status: "F")

실패 시 모든 엔드포인트는 {"status": "F", "message": "..."} 를 반환합니다. 클라이언트는 HTTP 상태 코드가 아니라 항상 status 필드로 분기해야 합니다. 아래는 서버가 반환할 수 있는 모든 실패 message 를 엔드포인트별 + 공통 검증/시스템 오류로 정리한 것입니다.

※ status: "F"(서버 응답)와 status: "NG"(요청 본문, RCS가 실패 물품에 대해 보냄)는 다릅니다. "F"는 서버가 호출을 거부/실패한 것이고, "NG"는 정상 수신되어 로그에 기록되는 실패 물품으로 서버는 이를 수락하고 "S"를 반환합니다.

공통 — 요청 검증 (HTTP 400)

모든 POST 엔드포인트에 적용. 가장 먼저 실패한 필드의 메시지가 반환됩니다.
